## 🎯 목표 ① 이직 — 넥슨 빌링/플랫폼

### 타겟과 현재 상태

- **1순위 타겟**: 넥슨코리아 플랫폼본부 > 플랫폼파운데이션그룹 (구 인텔리전스랩스 빌링팀 — 인증·계정·빌링 등 핵심 공통 서비스)
- **병행 모니터링**: NCS개발팀 / 라이브웹개발팀 / 운영플랫폼팀
- **공고 모니터링 키워드**: 상시채용 성격이 강해 "빌링팀" 이름으로 안 뜰 수 있음 → "플랫폼본부 / 플랫폼파운데이션그룹 / 인증 / 세션 / 빌링"
- **현재 상태**: C#/.NET 10년차·과장급, MSSQL/SP 실무, ASP.NET MVC5 실무(리팩토링), Minimal API 학습 22편

### 전략 재평가 (2026-09-28) — 미니 프로젝트는 타당한가

마지막으로 확인된 넥슨 C# 빌링 공고(2025-01-14 게시)와 대조한 결과.

| 공고 원문 | 현재 | 미니 프로젝트가 채우나 |
| :--- | :--- | :--- |
| 주요업무: "게임 재화 개발, 충전·사용 기능 구현" | 실무 경험 있음 | ✅ 도메인 정확히 일치 |
| C#/.NET Framework 3년+ | 10년차 | 불필요 — 이미 충족 |
| RDBMS (SQL Server, MySQL 등) | MSSQL·SP 실무 | 거의 불필요 — 이미 충족 |
| TCP/IP·HTTP 이해 + WebAPI 개발 경험 | MVC5 실무, Core 학습 중 | 일부 (README 서술, ASP.NET Core 실전) |
| **AWS 등 클라우드 환경 개발 경험** | **없음** | **❌ → ✅ MVP 안으로 이동** (기존엔 Phase 5 "여유 시"였음) |
| 멱등성·동시성·EF Core·Dapper | — | 공고에 없음. 핀테크 결제 일반론 + 본인 면접 감점 경험에서 나온 추론 |

**판단**: 방향(재화 충전·차감 도메인)은 타당하다. 다만 기존 계획에는 세 가지 문제가 있었고, 이번 개편에서 고쳤다.

1. **10년차는 경력기술서로 뽑힌다.** 면접관은 "회사에서 실제로 어떻게 했나"를 묻는다. 실무의 결제·SP 경험이 토이 프로젝트보다 강한 증거인데, 시장 조사의 최대 갭("실무 경험 有, 서사화 안 됨")을 다루는 작업이 로드맵에 없었다. → **Phase 0 경력기술서 추가**
2. **필수 요건인 AWS가 맨 뒤였다.** 지금 증거가 0인 유일한 자격요건이다. → **AWS 최소 배포를 MVP 정의에 포함**
3. **타겟 리스크.** 확인된 C# 빌링 공고는 2025-01이 마지막이고, 2026-04 플랫폼본부 공고는 Java 5년+ (Kafka·Redis·DDD)다. 빌링 신규 채용이 Java로 넘어가는 중일 수 있다 (2026년 C# 공고를 "못 찾은 것"이지 "없다"는 확정은 아님). → **월 1회 타겟 점검 + 대안 타겟 명시**

### 미니 프로젝트를 하는 이유 — 딱 세 가지

프로젝트 자체가 목표가 아니다. **지금 보여줄 증거가 없는 것**을 만들기 위해 한다.

1. **AWS 경험** — 필수 요건, 현재 0
2. **ORM으로 트랜잭션·동시성을 다뤄본 경험** — 실제 면접 감점 이력
3. **ASP.NET Core WebAPI 실전 경험** — 실무는 MVC5뿐

> **판단 기준**: 경력기술서에서 **이미 실무 증거가 있는 역량은 프로젝트에서 뺀다.** 예) 회사에서 멱등성을 구현한 적이 있다면 → 프로젝트에서 재구현하지 말고 경력기술서에 쓴다.

### 무기 — "C# 언어"가 아니라 "결제 도메인 역량"

결제/빌링 백엔드는 언어와 무관하게 5가지로 수렴한다: **멱등성 · 동시성 제어 · 트랜잭션 정합성 · RDBMS 모델링/최적화 · 대용량 트래픽 대응**.

SP 실무 경험은 약점이 아니라 **차별화 자산**. 단, EF Core/Dapper와 SP를 **"언제, 왜" 구분해 쓰는지** 설명할 수 있어야 한다. ORM은 "사용 경험"이 아니라 **트랜잭션·동시성 등 문제 해결 능력**으로 검증받는다.

### 트랙 A. 미니 프로젝트 — 재화 충전·차감 API

> **한 줄 정의**: 재화 충전/차감 API를 **AWS에 배포**한 것. 단, **멱등성·동시성·트랜잭션을 제대로 처리한 것.**
> 기능은 딱 3개. "기능 많이"가 아니라 **"경력기술서의 빈칸을 깊게"**.

**스택**: ASP.NET Core Web API (.NET 최신) · MSSQL 단일 · **AWS 최소 배포 (RDS + ECS 또는 EC2)**

**데이터 접근 이원화 (원칙)**: 명령/거래(충전·차감)는 **SP + Dapper**, 도메인 상태(Wallet)는 **EF Core**. "언제 SP를, 언제 ORM을 쓰는가"를 코드로 증명하는 것이 ORM 감점 방어의 핵심.

| API | 기능 | 증명하는 역량 | 데이터 접근 |
| :--- | :--- | :--- | :--- |
| `POST /wallet/charge` | 재화 충전 | **멱등성** (Idempotency-Key, 중복 충전 차단) | SP + Dapper |
| `POST /wallet/consume` | 재화 차감 | **동시성** (락으로 잔액 음수 방지) | SP + Dapper |
| `GET /wallet/{id}` | 잔액/거래 이력 조회 | 조회 | Dapper |

**깊이 — 핵심 3가지** (경력기술서에 실무 증거가 있으면 해당 항목 생략)

1. **멱등성** — `Idempotency-Key` 헤더. 같은 키 재요청 시 저장하지 않고 첫 결과 반환 (토스페이먼츠 규격 참고: UUID·TTL, 처리 중 재요청 409, 완료 재요청은 최초 결과 재반환)
2. **동시성** — 동시 차감으로 잔액이 음수가 되는 상황을 **일부러 재현** → 락으로 해결. Before(터짐)/After(막힘) 로그 기록. **EF Core RowVersion(낙관적) vs SP UPDLOCK(비관적)을 같은 시나리오로 비교** — ORM 감점 방어의 핵심 소재
3. **트랜잭션** — 차감 + 이력 기록을 하나의 트랜잭션으로 묶고, 중간 실패 시 롤백 검증

**기록 방식**: README에 **"문제 → 원인 → 해결 → 결과"** 형식으로 서술 → 면접 소재로 그대로 사용. TCP/IP·HTTP 이해는 "HTTP 상태 코드 설계 근거", "멱등성의 PUT vs POST 시맨틱", "재시도/타임아웃의 TCP 커넥션 관점 판단"으로 README에 서술.

**하지 않는 것**: 프론트 UI, 보안키패드, 실제 PG 연동, 정산, 환불, BFF, SignalR, 실시간 알림.

## 🗣️ 목표 ② 영어 — 회의 주관 + OPIc

### 목적

- **목적 1 — 실전**: 약 1년 뒤(2027년 가을 예상) 영어 프로젝트에서 **PM 대신 영어 회의를 직접 주관**한다.
- **목적 2 — 이직**: 이력서에 영어 역량을 정량적으로 보여줄 **자격증 취득**.

### 현재 상태와 갭

| 구분 | 상태 |
| :--- | :--- |
| 강점 | 2년 미국 어학연수 — 일상 회화(중학생 수준) 가능, 듣기·발화에 대한 두려움 없음 |
| 갭 | **비즈니스 회화** — 격식 있는 표현, 기술 용어, **회의를 이끄는 화법**(어젠다 제시 → 의견 조율 → 결론·액션 아이템 정리) |

> 즉 "영어를 못해서"가 아니라 **"회의를 운영하는 표현 세트가 없어서"**가 문제. 새로 배우는 게 아니라 채워 넣는 작업이다.

### 자격증 — OPIc 선택

국내 취업용 스피킹 자격증은 토익스피킹과 OPIc 양대 산맥. 둘 다 문법 단독 시험이 아닌 스피킹 통합 평가라 "문법 제외" 조건은 모두 충족하지만, 목적 1까지 겨냥하면 차이가 난다.

| | 토익스피킹 | **OPIc ✅** |
| :--- | :--- | :--- |
| 형식 | 정형화된 11문항 (약 20분) | 설문 기반 맞춤 주제 + 롤플레이 (약 15문항, 40분) |
| 대비 방식 | 템플릿 암기로 대응 가능 | 암기가 잘 안 통함 — 즉흥 대응력 필요 |
| 목적 1과의 연결 | 낮음 — 시험 점수와 실전 회화력이 따로 놀 수 있음 | **높음 — 준비 과정 자체가 회의 대응 훈련** |
| 채용 인정도 | 공기업·일부 대기업 선호 | 삼성·LG 등 다수 대기업이 실무 영어 지표로 선호 |

- **1차 목표**: **IH** (Intermediate High) — 이직 지원 시 무난한 수준
- **2차 목표**: **AL** (Advanced Low) — 회의 주관에 필요한 순발력까지 확보

### 주간 루틴

| 무엇 | 빈도 | 시간대 | 목적 |
| :--- | :--- | :--- | :--- |
| 1:1 화상영어 (비즈니스·회의 롤플레이 코스) | 주 2~3회, 회당 25분 내외 | 점심 또는 퇴근 후 | 실제로 말하는 양 확보 |
| 쉐도잉 / 리스닝 (비즈니스 대화, 기술 발표 영상) | 매일 15~20분 | 출퇴근 | 비즈니스 톤과 표현 흡수 |
| 셀프 녹음 → 다시 듣기 | 주 1회 | 주말 | 필러("um, like")·시제·답변 길이 점검 |
| 표현 뱅크 추가 | 수시 | — | 쓸 만한 표현을 상황별로 누적 |

### 세부 준비 과정

**Phase 0 — 진단·세팅**
- [ ] OPIc 모의 문항 (자기소개 / 업무 묘사 / 경험 / 롤플레이) 답변 녹음 → 현재 등급 추정
- [ ] 녹음 기반 약점 목록 작성 (어휘 부족 / 시제 오류 / 답변이 짧음 / 필러 과다 등)
- [ ] 화상영어 서비스 선택 (비즈니스·회의 코스가 있는 곳) + 주간 루틴 확정
- [ ] 표현 뱅크 파일 만들기 (상황별: 회의 / 기술 설명 / 스몰토크)

**Phase 1~2 — 비즈니스 표현 기반**
- [ ] 회의 화법 4단계 프레이즈 각 5개 이상 입에 붙이기 (아래 표 참고)
- [ ] 기술 설명 영어: 미니 프로젝트를 **3분 영어 설명**으로 만들기 — 멱등성·동시성·트랜잭션을 영어로 설명 (이직 영어 면접 대비와 겸용)
- [ ] 화상영어에서 "업무 상황 롤플레이" 위주로 수업 요청 (스탠드업, 이슈 보고, 일정 협상)
- [ ] 이메일·슬랙 수준의 업무 영어 문장 작성 연습 (회의 전후 커뮤니케이션 대비)

**Phase 3 — OPIc 집중**
- [ ] 시험 구조 숙지 — 사전 설문(Background Survey)은 연결하기 쉬운 주제로 일관되게 선택, 난이도(Self-Assessment)는 목표 등급에 맞춰 선택
- [ ] 유형별 답변 **뼈대** 준비 (대본 암기 X) — 묘사 / 루틴 / 과거 경험 / 롤플레이(질문하기·문제 해결) / 돌발 질문
- [ ] 매일 1문항 녹음 → 답변 길이 1분 30초 이상, 구체적 에피소드 포함 여부 점검
- [ ] 실전 모의고사 2~3회
- [ ] 🏁 **OPIc 응시 → IH 이상**

**Phase 4 — 회의 주관 실전**
- [ ] 튜터와 **30분 모의 회의** 리허설 — 내가 진행자 역할 (어젠다 오픈 → 토론 → 정리)
- [ ] 영어 회의록·액션 아이템 작성 연습
- [ ] 사내 영어 회의가 있다면 참관 → 일부 진행 → 전체 진행 순으로 단계적 노출
- [ ] 백엔드/결제 도메인 기술 영어 지속 보강

**Phase 5 — 선택**
- [ ] OPIc **AL** 재도전

### 회의 주관 화법 — 표현 뱅크 시작점

| 단계 | 표현 예시 |
| :--- | :--- |
| **열기** (어젠다 제시) | "Let's get started. Today we have three items on the agenda." / "The goal of this meeting is to decide on …" |
| **의견 구하기** | "What are your thoughts on this?" / "Does anyone have concerns about this approach?" / "I'd like to hear from the backend side first." |
| **조율하기** (이견·시간 관리) | "I see your point, but have we considered …?" / "Let's take this offline and move on to the next item." / "To keep us on time, let's limit this to five minutes." |
| **정리하기** (결론·액션 아이템) | "So to summarize, we've agreed to …" / "The action items are: …, owned by …, by Friday." / "Let's follow up on this next week." |

> ⚠️ 자격증(목적 2)은 회의 주관 준비(목적 1) 과정에서 따라오는 **부산물**로 취급한다. 점수를 위해 대본 암기로 방향이 틀어지지 않도록 유의.

## ⚙️ 운영 원칙

1. **여유 2주 = 구현, 바쁜 2주 = 문서·복습·인강.** 바쁠 때 코드 진도가 멈춰도 정상. 경력기술서는 바쁜 주에 하기 좋은 작업이다.
2. **순연은 실패가 아니라 기본값.** 실무가 터지면 해당 Phase를 통째로 미룬다. 체크리스트는 마감이 아니라 가이드.
3. **트랙별 시간대 분리.** 코테 = 아침, 영어 = 출퇴근·점심, 프로젝트·경력기술서 = 저녁·주말, AWS = 여유 시.
4. **바빠도 끊지 않는 최소 단위**: 코테 1문제 + 영어 리스닝 15분. 이 둘만 유지되면 루틴은 살아 있다.
5. **가장 중요한 마일스톤은 두 개** — 이직: 경력기술서 + AWS에 배포된 MVP (= 지원 가능 상태), 영어: OPIc IH.
6. **프로젝트는 빈칸만 채운다.** 실무 증거가 있는 역량은 프로젝트로 재구현하지 않는다.
7. **타겟은 월 1회 점검.** 공고가 MVP 전에 뜨면 "개발 중" 상태로라도 지원. C# 공고가 안 보이면 대안 타겟으로 넓힌다.

## 📎 부록

### 배경 — 왜 로드맵을 다시 짰나

- 기존 로드맵(.NET 10 & Azure)은 "기술 스택을 순서대로 넓힌다"는 방향이었으나, 목표 없는 확장은 방향성이 흐려짐
- 시장 조사 결과 **"C#/.NET 진영 대기업"이라는 전제가 국내 현실과 어긋남** — 금융권은 Java/Spring, 대형 게임사 서버도 C++/Java/Go 위주. C#/.NET은 제조 MES/ERP, SI/솔루션, 소수 게임 스튜디오, AI/SaaS 스타트업 등 **니치 시장**
- 그중 **넥슨코리아 플랫폼본부 빌링/플랫폼 공통서비스**가 요구 스펙·연차·도메인 정합성 면에서 가장 구체적이고 반복적으로 확인된 타겟
- 2026-09 개편 ①: 1년 뒤 영어 프로젝트(회의 주관) 일정이 생겨 **영어를 두 번째 목표로 추가**
- 2026-09 개편 ②: 공고 원문 재대조 결과 **경력기술서(Phase 0) 추가, AWS를 MVP로 이동, EF Core 범위 축소, 타겟 점검 추가**
