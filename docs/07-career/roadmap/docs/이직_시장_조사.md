# 1. 조사 요약 (TL;DR)

- **"C#/.NET 진영 대기업"이라는 전제는 국내 현실과 어긋난다.** 금융권(은행/카드/보험/증권)은 Java/Spring이 압도적이고, 대형 게임사의 게임 코어 서버도 C++/Java/Go 위주다. C#/.NET은 **제조 MES/ERP, SI/솔루션, 헬스케어, 소수 게임 스튜디오, AI/SaaS 스타트업**으로 이루어진 **니치 시장**이다.
- **그 니치 안에서 가장 구체적이고 반복적으로 확인된 대기업 타겟이 넥슨코리아**다. 게임 코어 서버(C++)와 별개로 **빌링·고객센터·라이브웹·운영플랫폼 등 비즈니스/플랫폼 백엔드에 C#/.NET 전담 조직이 실재**한다.
- **단, 넥슨 내부에서도 C#/.NET은 레거시·운영 성격이고, 신규 투자·모던 스택(Kafka·Redis·DDD·K8s)은 Java/Spring 계열로 이원화**되고 있다. C#를 주력으로 유지하되 Java/Spring 생태계를 읽을 수 있는 수준까지 확보하면 지원 폭·생존력이 올라간다.
- **합격을 가르는 핵심은 언어가 아니라 "결제 도메인 역량"**이다: 멱등성, 동시성 제어, 트랜잭션 정합성, RDBMS 최적화, 대용량 트래픽. 이 다섯은 C#이든 Java이든 결제/빌링 백엔드에서 공통으로 검증된다.
- **연봉 관점**: C#/.NET은 국내 백엔드 스택 연봉 상위(C++·PHP·Python·Java)에 별도 집계되지 않을 만큼 니치다. 몸값을 올리려면 언어 단일 역량이 아니라 도메인(결제)·클라우드·아키텍처를 얹어야 한다.

# 2. .NET 생태계 트렌드 (2025-2026) — 배경

이직 준비의 기술적 배경으로 참고할 최신 동향.

- **.NET 10 (LTS)**: 2025년 11월 출시, 2028년 11월까지 지원. 신규/전환 프로젝트의 목표 지점. .NET 8 LTS·9 STS는 2026년 11월 지원 종료.
- **.NET Framework 4.8/4.8.1**: 명시적 종료일은 없으나(Windows OS 종속) 신규 기능·성능·언어 발전은 사실상 동결. "지원됨 = 보안 패치만". → **넥슨 빌링이 .NET Framework 기반이라는 점은 "레거시 운영 역량"이 통한다는 의미**이기도 하다.
- **C# 14**: 확장 멤버, `field` 키워드, 파일 기반 앱 등. C#는 TIOBE 2025 '올해의 언어'로 선정될 만큼 상승세.
- **웹 스택**: ASP.NET Core 중심. Minimal API 자리잡음. Blazor는 통합 렌더링 모델로 재정비. .NET Aspire(클라우드 네이티브) 부상.
- **DB**: SQL Server 2025(2025년 11월 GA) — 네이티브 VECTOR 타입, 벡터 검색, 네이티브 JSON 등 AI-ready 기능. EF Core가 사실상 표준 ORM, Dapper는 고성능 구간 병용.
- **클라우드**: 글로벌 AWS 1위·Azure 2위. **국내 게임업계(넥슨 포함)는 AWS 비중이 높음** → 타겟 기준 클라우드는 AWS.

# 3. 국내 C#/.NET 백엔드 채용 시장의 실제 구조

"대기업이 C#/.NET을 쓰느냐"가 아니라 **"어떤 산업군/조직이 쓰느냐"**로 이해해야 한다.

```
[강한 확신 · 실제 대기업]
  넥슨(플랫폼본부/구 인텔리전스랩스) ─ 빌링/NCS/라이브웹/개인화/운영플랫폼
      └ C#/.NET Framework/Core, MSSQL/MySQL, HTTP/RESTful, JS 병행, AWS

[중간 확신 · 대기업 계열사]
  카카오게임즈(메타보라) ─ C#/C++/Linux/MySQL, 7년+

[확인됨 · 중견/성장기업 (현대적 스택)]
  랭코드(AI Agent SaaS) ─ ASP.NET Core, EF Core, Next.js
  클라우드호스피탈(헬스케어) ─ .NET Core, MSSQL/PostgreSQL, EF Core, SignalR, Azure, Docker/K8s/Terraform
  이지케어텍(병원정보시스템) ─ .NET 풀스택

[확인됨 · 다수/안정적 물량 (레거시 성격)]
  제조 MES/ERP, 반도체 장비 제어, 병원 솔루션 ─ C#, MSSQL, 온프레미스

[미확인/반증 · 과신 금지]
  금융권(카드/보험/증권) ─ Java/Spring 주류, C#/.NET 근거 못 찾음
  대형 SI(삼성SDS/LG CNS/SK C&C) ─ C#/.NET 명시 확인 못 함
  엔씨/크래프톤/NHN 본진 ─ 대부분 Java/C++ 추정
```

**시사점**: 좁은 시장에서는 "넓게 뿌리기"가 아니라 "소수 타겟 정밀 타격"이 정답. 그래서 넥슨 빌링/플랫폼으로 타겟을 좁혔다.

# 4. 타겟 확정 — 넥슨코리아 빌링/플랫폼

- **1순위 타겟**: 넥슨코리아 플랫폼본부 > 플랫폼파운데이션그룹 (구 인텔리전스랩스 빌링팀 — 인증·계정·빌링 등 핵심 공통 서비스)
- **인접 조직(병행 모니터링)**: NCS개발팀(고객센터/상담), 라이브웹개발팀, 개인화개발팀, 운영플랫폼팀
- **타겟 선정 이유**:
  1. 게임 코어 서버(C++)와 별개로 C#/.NET 비즈니스/플랫폼 백엔드가 **반복적·구체적으로 확인**됨
  2. 요구 연차(3~5년)가 10년차에게 낮게 잡혀 있어 **리드·책임급으로 포지셔닝 여지**
  3. 재화 충전/사용/정산 도메인이 본인 실무(빌링·SP·MSSQL)와 정합
  4. 상시채용 성격 → 준비된 상태를 유지하면 기회 반복
- **모니터링 팁**: "빌링팀" 명칭이 조직 개편으로 사라질 수 있으니 "플랫폼본부 / 플랫폼파운데이션그룹 / 인증 / 세션 / 빌링" 키워드를 함께 추적. 공식 채용 페이지(career.nexon.com) 주기 확인.

## 5-3. C# 빌링 공고에서 확인된 스펙 (2025.01 기준)

**필수**

**우대/보조**
- Java/Spring 경험 (혼합팀 협업 대비)
- 게임 재화/과금/결제 도메인 이해 (업무 설명에서 유추)

**전형 절차** (인접 공고 기준): 서류 → 코딩테스트 → 면접 → 최종합격
→ **10년차에게도 코딩테스트 단계 존재.** 실제 면접 후기에 "MVC가 뭔가요?" 같은 기본 개념 질문 사례 있음 → 기본 개념을 정확·간결히 설명하는 능력이 시니어 평가 기준.

# 6. 넥슨의 언어별 스택 이원화 (핵심 발견)

이번 조사에서 가장 중요한 구조적 발견.

| 구분 | C#/.NET 계열 | Java/Spring 계열 |
| :--- | :--- | :--- |
| 담당 | 빌링, 고객센터(NCS), 라이브웹, 운영 백엔드 | 신규 플랫폼(인증·계정·빌링 공통), BFF, 실시간 알림 |
| 스택 | C#/.NET Framework, SQL Server/MySQL, WebAPI, AWS | Java/Spring Boot, Aurora/MySQL/PostgreSQL, Kafka/Kinesis, Redis, Docker, GitLab CI/CD, Grafana/Prometheus/Loki, DDD/클린아키텍처 |
| 성격 | 레거시·운영 | 모던 MSA·신규 투자 |

**해석**: 넥슨은 "게임 코어 서버=C++"와 "비즈니스/플랫폼=C#/.NET 또는 Java" 트랙이 공존하며, 후자 안에서도 **레거시 C#와 신규 Java가 병존**한다. 2026년 신규 투자 흐름은 Java 쪽에 집중.

**전략적 함의**:
- C#/.NET 빌링 코드베이스는 살아있고, SP·MSSQL 실무 강점이 정확히 그 자리에 맞음 (좋은 소식)
- 다만 C# 단일 고집 시 성장 트랙이 좁아질 수 있음 → **Java/Spring·Kafka·Redis·DDD를 "읽고 이해하는" 수준까지는 확보** 권장 (냉정한 소식)

> ⚠️ **정직성 주의**: C# 빌링 공고에는 ORM(EF Core/Dapper)·저장프로시저·Redis·Kafka·Docker·CloudWatch·멱등성·트랜잭션 상세가 **명시된 바 없음(전부 "미확인")**. 위 모던 스택은 넥슨 **Java 계열 공고**에서 확인된 것이다. C# 빌링 확인 키워드는 오직: C#/.NET Framework, SQL Server/MySQL, TCP/IP, HTTP, WebAPI, AWS.

# 7. 결제/빌링 도메인 공통 요구 역량 (네카라쿠배·핀테크 비교)

C# 빌링의 내부 구현 상세가 비공개이므로, **결제 도메인 일반의 베스트프랙티스**를 네카라쿠배·핀테크 공개 자료에서 확보했다. 언어(C#/Java)와 무관하게 결제 백엔드는 아래로 수렴한다.

## 7-1. 핀테크/커머스 결제 백엔드 스펙 (비교 참고용)

| 기업 | 도메인 | 언어 | ORM | DB/캐시 | 메시징 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 카카오페이 | 결제/정산/머니 | Java/Kotlin, Spring | 미확인 | RDB, Redis | Kafka |
| 네이버페이 | 정산/카드결제 | Java, Spring Boot | 미확인 | MongoDB, Redis | Kafka |
| 라인페이 | 결제/송금 | Java, Spring/JPA | JPA | RDB | 미확인 |
| 쿠팡페이 | 공통 플랫폼 | Java, Spring | 미확인 | 미확인 | 미확인 |
| 우아한형제들 | 정산 플랫폼 | Java, Spring Boot | JPA | MySQL | Kafka(+Debezium CDC) |
| 카카오스타일 | 결제&정산 | Java/Kotlin, Spring | JPA/Hibernate | RDBMS | 미확인 |

## 7-2. 결제 도메인 공통 5대 역량

1. **멱등성(Idempotency)** — 중복 결제 요청 차단. 토스페이먼츠 규격: 모든 POST API에 `Idempotency-Key` 헤더(UUID·최대 300자·15일 유효), 처리 중 재요청 409, 완료 재요청은 최초 결과 재반환.
2. **동시성 제어** — 재화/잔액 동시 차감 시 음수·이중차감 방지. 낙관적 락(RowVersion) vs 비관적 락(`FOR UPDATE`/`UPDLOCK`).
3. **트랜잭션 정합성** — 외부 결제 성공 + 내부 DB 실패 시 정합성. 우아한형제들: **트랜잭셔널 아웃박스 패턴**(비즈니스 데이터+outbox를 로컬 트랜잭션으로 동시 커밋, Debezium CDC로 Kafka 발행, consumer는 event id로 멱등 처리). 토스뱅크: **보상 트랜잭션(Orchestration Saga)**으로 환전 처리, 상태머신으로 표현.
4. **RDBMS 모델링/최적화** — 원장 설계, 인덱스, 실행계획.
5. **대용량 트래픽 대응** — 고TPS/저지연.

## 7-3. 넥슨 내부 근접 사례

- **NDC2015 "분산 데이터베이스 트랜잭션 설계와 구현"** (마비노기 듀얼, MariaDB+Redis, 유저 단위 수평분할 환경의 유저 간 거래 트랜잭션 구현). 결제는 아니나 분산 트랜잭션 사례로 근접.

**결론**: 미니 프로젝트(재화 충전/차감)에 **멱등성 + 동시성 + 트랜잭션(+아웃박스)**을 구현하면, 언어가 C#이어도 이 공통 역량을 그대로 증명할 수 있다. 이것이 "무기는 언어가 아니라 도메인 역량"의 근거.

# 8. 현재 기술스택 vs 요구 기준 — 갭 분석

| 영역 | 요구 수준 | 현재 상태 | 갭 |
| :--- | :--- | :--- | :--- |
| C#/.NET | 3년+ 상당 | 10년차, 기초 45편 정리 | 충족 |
| MSSQL | 기본 | 실무 보유 | 작음 |
| SP(저장프로시저) | (공고 미명시, but 빌링에 흔함) | 실무 강점 | **강점 자산** |
| MySQL | 병기 요구 | 약함/미확인 | 중간 — 기본 숙지 필요 |
| ASP.NET Core WebAPI | 요구 | 학습 중(Minimal API 22편) | 중간 — 실전 필요 |
| ORM(EF Core/Dapper) | 문제 해결력까지 검증 | 학습 중 | **중간~큼 — 면접 감점 경험, 트랜잭션·동시성 중심 보강** |
| TCP/IP·HTTP | 서류 단계부터 명시 | 본인 인지상 약함 | 중간 — 단, 10년차는 온보딩 벼락치기 유효 |
| AWS | 명시 | 미착수 | 중간 — 전환 학습 필요 |
| 결제 도메인 역량 | 핵심 | 실무 경험 有, 서사화 안 됨 | **큼 — 미니 프로젝트로 실증 필요** |
| 아키텍처/리드 서사 | 10년차 필수 | 경험 有, 언어화 안 됨 | **큼 — 콘텐츠화 시급** |
| 코딩테스트 | 시니어도 존재 | 불확실 | 감각 유지 필요 |

**종합**: 신기술(Kafka/Azure) 부족보다 **① 결제 도메인 역량의 서사화 ② ORM 문제 해결력 ③ 기본기 설명력**이 실제 당락을 가르는 갭. 미니 프로젝트와 지원 직전 온보딩으로 메우는 것이 전략.

# 9. 조사의 한계 (Caveats)

- 본 조사는 웹 검색으로 접근 가능한 채용 공고·기술블로그·컨퍼런스 자료 표본에 기반하며 **전수조사가 아니다.** 사내 추천·헤드헌팅 경로의 수요는 미반영.
- 넥슨 공식 채용 상세 페이지는 로봇 차단으로 직접 열람이 불가해, 원티드/링커리어/잡코리아/비즈니스피플 등 **재게시 스냅샷에 의존**했다. 공고는 수시 마감되므로 특정 시점 정보다.
- C# 빌링 공고의 ORM·SP·Redis·Kafka·Docker·멱등성·트랜잭션·.NET 정확한 버전은 **공개 정보에 없어 전부 "미확인"**이다. 7장의 결제 베스트프랙티스는 핀테크 공개 사례 기반이지 넥슨 내부 실사용 확인이 아니다.
- 금융권·대형 SI·NC/크래프톤/NHN의 "C#/.NET 미사용"은 "확인 못 함"이지 "확실히 안 씀"이 아니다.
- 연봉 데이터(점핏 2025 등)는 C#/.NET을 별도 집계하지 않아 Java 근사치로만 참고했다. 표본·플랫폼 편향 가능.
- **지원 전 반드시 넥슨 공식 채용 페이지에서 최신 공고를 재확인할 것.**
