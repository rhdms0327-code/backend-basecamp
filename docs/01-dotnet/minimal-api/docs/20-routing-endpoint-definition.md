> ASP.NET Core의 라우팅 시스템은 단순한 주소 매핑을 넘어 애플리케이션의 전체 파이프라인을 관제하는 핵심 메커니즘입니다.

---

클라이언트가 HTTP 요청을 보내면, 라우팅 엔진은 내부의 라우팅 테이블을 탐색하여 일치하는 엔드포인트(Endpoint)로 요청을 디스패치(Dispatch)합니다. 엔드포인트는 요청을 처리하는 최하단의 실행 코드 단위이며, 구현 기술에 상관없이 동일한 추상화 수준으로 다루어집니다.

## 🏗️ 아키텍처적 구조 대조: Controller 방식 vs Minimal API

기존의 Controller 방식과 Minimal API의 대리자(Delegate)/람다 방식은 엔드포인트를 구성하는 아키텍처 측면에서 명확한 설계 의도의 차이를 보여줍니다.

### 기존 Controller 방식
하나의 엔드포인트를 노출하기 위해 클래스를 선언하고, 기본 클래스를 상속받으며, 액션 메서드를 정의해야 했습니다.
이는 필연적으로 많은 보일러플레이트(Boilerplate) 코드를 유발하며, 런타임에 리플렉션을 통해 라우팅 정보를 탐색하므로 결합도가 높고 무거운 구조를 가집니다.

### Minimal API 방식 (대리자 및 람다)
`MapGet`, `MapPost`와 같은 메서드에 익명 함수나 람다 식을 직접 전달하여 엔드포인트를 정의합니다.
불필요한 클래스 계층 구조를 제거하여 코드의 가독성을 극대화하고, 애플리케이션 시작(Startup) 시점에 라우팅과 실행 로직이 물리적으로 가장 가깝게 매핑되도록 설계되었습니다.

## 💡 통합 엔드포인트 라우팅의 이점

현대의 엔드포인트 라우팅은 요청 처리 단위를 독립된 객체로 완전히 분리했습니다. 덕분에 미들웨어 파이프라인에서 엔드포인트의 메타데이터를 사전에 검사할 수 있어, 보안(인가)이나 CORS 정책을 일관되게 적용할 수 있는 유연성을 제공합니다.

## 🚦 라우팅의 핵심 역할 2가지

라우팅은 단순히 주소를 연결하는 것을 넘어 내부적으로 2단계로 작동합니다.

- **경로 일치 (Route Matching)**: 들어온 URL 주소를 보고 "어떤 엔드포인트(코드)랑 매칭되지?"를 찾아내서 기록해 두는 단계 (`UseRouting`).
- **엔드포인트 실행 (Endpoint Execution)**: 매칭된 최종 목적지 코드를 실제로 실행하는 단계 (`UseEndpoints` 또는 `Map~` 메서드들).

## 🎯 엔드포인트(Endpoint)란 무엇인가?

앱이 요청을 받았을 때 실제로 실행되는 **최종 목적지(함수/코드 블록)**를 뜻합니다. 컨트롤러의 액션 메서드, Razor Pages, 그리고 `app.MapGet()`으로 만드는 최소 API(Minimal API)가 모두 엔드포인트입니다.

엔드포인트는 한 번 매칭되면 인증(Authorization)이나 CORS 같은 미들웨어가 이 정보를 가져가서 *"이 주소는 로그인한 사람만 들어올 수 있네?"* 하고 검사할 수 있게 해줍니다.

## 📝 가장 많이 쓰는 라우트 템플릿 제약 조건 (Constraints)

URL 주소에서 변수를 뽑아낼 때, 잘못된 값이 들어오면 필터링해 주는 규칙입니다.

- `products/{id:int}` ➡️ `id`는 반드시 **숫자**여야 함 (`/products/123` 가능, `/products/abc`는 404 에러)
- `user/{name:alpha}` ➡️ `name`은 반드시 **영문 알파벳**이어야 함
- `files/{*path}` ➡️ 하위 경로 전체를 하나의 변수로 통째로 가져옴 (Catch-all)

## ⚡ 숏서킷 (Short-circuiting, 단락) - .NET 최신 중요 개념

특정 요청(예: `robots.txt`, 이미지 파일, 혹은 보안상 차단해야 하는 요청)은 뒤에 있는 무거운 미들웨어(인증, 데이터베이스 조회 등)를 굳이 거칠 필요가 없습니다.

이때 파이프라인 중간에서 *"더 이상 뒤로 가지 말고 여기서 바로 응답 끝내!"*라고 끊어버리는 것을 **숏서킷**이라고 하며, 성능 최적화에 아주 중요합니다.

- **숏서킷이 없을 때 (비효율적)**
  `요청` ➡️ `[로그인 검사]` ➡️ `[보안 검사]` ➡️ `[라우팅]` ➡️ `[DB 조회]` ➡️ `favicon.ico 리턴`
- **숏서킷을 쓸 때 (최적화)**
  `요청` ➡️ `[정적 파일 미들웨어]` ➡️ *"어? 아이콘 파일이네? 내가 줄게 끝!"* (숏서킷) ➡️ **바로 리턴** (뒤의 무거운 미들웨어는 실행조차 안 됨)

```csharp
var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// /robots.txt 요청이 오면 라우팅이나 인증 미들웨어를 거치지 않고 
// 여기서 바로 응답을 끝내버립니다. (서버 성능 최적화)
app.MapGet("/robots.txt", () => "User-agent: * \n Disallow: /")
   .ShortCircuit(); 

app.MapGet("/", () => "메인 페이지");

app.Run();
```

> 💡 **딱 요것만 기억하고 가세요!**<br/>
> "라우팅은 URL을 보고 **어디로 갈지 결정(Routing)**한 뒤, 중간에 필요한 보안 검사(미들웨어)를 거쳐, **최종 목적지(Endpoint)를 실행**하는 장치다."
