> 실수를 정수로 바꾸는 방법(버림·내림·올림·반올림)과, 정수 나눗셈·실수 오차·오버플로처럼 코테에서 자주 틀리는 숫자 계산을 정리했습니다. 예시의 결과값은 모두 xUnit 테스트로 실행해 확인했습니다.

---

## 1. 실수 → 정수: 버림·내림·올림

| 코드 | `2.7` | `-2.7` | 설명 |
| :--- | :--- | :--- | :--- |
| `(int)x` | `2` | `-2` | **버림**. 0 쪽으로 자른다 |
| `(int)Math.Truncate(x)` | `2` | `-2` | 버림. `(int)x`와 같다 |
| `(int)Math.Floor(x)` | `2` | `-3` | **내림**. 더 작은 정수로 |
| `(int)Math.Ceiling(x)` | `3` | `-2` | **올림**. 더 큰 정수로 |

- 양수만 나오면 `(int)x`와 `Math.Floor`가 같습니다. **음수가 섞이면 다릅니다.**
- `Math.Floor`, `Math.Ceiling`, `Math.Round`는 결과가 `double`이라 `(int)`를 한 번 더 붙여야 합니다.

---

## 2. 반올림: Math.Round의 함정

| 코드 | 결과 | 설명 |
| :--- | :--- | :--- |
| `Math.Round(2.5)` | `2` | 기본값은 **오사오입**(가장 가까운 짝수로) |
| `Math.Round(3.5)` | `4` | 짝수 쪽으로 가므로 4 |
| `Math.Round(2.5, MidpointRounding.AwayFromZero)` | `3` | 학교에서 배운 **사사오입** |
| `Math.Round(-2.5, MidpointRounding.AwayFromZero)` | `-3` | 음수도 0에서 먼 쪽으로 |
| `Math.Round(3.14159, 2)` | `3.14` | 소수 둘째 자리까지 |
| `Convert.ToInt32(2.5)` | `2` | `Convert`도 오사오입 |
| `Convert.ToInt32(2.7)` | `3` | `Convert`는 버림이 아니라 반올림 |

> 문제에서 "반올림"이라고 하면 보통 사사오입입니다. `Math.Round(x, MidpointRounding.AwayFromZero)`를 씁니다. `Convert.ToInt32(double)`은 버림이 아니라 반올림이니 정수 부분을 구할 때 쓰면 안 됩니다.

## 3. 정수 나눗셈과 나머지

| 코드 | 결과 | 설명 |
| :--- | :--- | :--- |
| `7 / 2` | `3` | 정수끼리 나누면 몫만 남는다 |
| `-7 / 2` | `-3` | 0 쪽으로 버린다 (내림이 아님) |
| `7 % 3` | `1` | 나머지 |
| `-7 % 3` | `-1` | 나머지의 부호는 앞의 수를 따른다 |
| `7 / 2.0` | `3.5` | 한쪽이 실수면 실수 나눗셈 |
| `(double)7 / 2` | `3.5` | 변수일 때는 형변환으로 |
| `(7 + 2 - 1) / 2` | `4` | 양수의 **올림 나눗셈**: `(a + b - 1) / b` |
| `(int)Math.Ceiling(7 / 2.0)` | `4` | 올림 나눗셈의 다른 방법 |

> `Math.Ceiling(7 / 2)`는 컴파일 오류가 납니다. 정수 나눗셈 결과(`int`)를 넘기면 `Ceiling(double)`과 `Ceiling(decimal)` 중 어느 쪽인지 정할 수 없기 때문입니다. 설령 된다 해도 `7 / 2`가 이미 3이라 올림이 안 됩니다. `7 / 2.0`처럼 실수로 나눕니다.

## 4. 실수 오차

| 코드 | 결과 | 설명 |
| :--- | :--- | :--- |
| `(int)(2.3 * 100)` | `229` | `2.3 * 100`이 229.99999…라 버리면 229 |
| `(int)Math.Round(2.3 * 100)` | `230` | 반올림하면 230 |
| `(int)(2.3m * 100)` | `230` | `decimal`(`m` 접미사)은 10진수라 오차가 없다 |
| `0.1 + 0.2 == 0.3` | `false` | 실수는 `==`로 비교하지 않는다 |
| `Math.Abs(0.1 + 0.2 - 0.3) < 1e-9` | `true` | 아주 작은 차이 이내면 같다고 본다 |

> 돈이나 소수 자릿수가 정확해야 하는 계산은 `decimal`을 쓰거나, 처음부터 정수 단위(원, 센트)로 바꿔서 계산합니다.

## 5. 제곱근과 거듭제곱

```csharp
long n = 121;
long r = (long)Math.Sqrt(n);     // 11
bool isSquare = r * r == n;      // 제곱수 판별: 실수 결과를 그대로 비교하지 말고 정수로 되돌려 확인

int p = (int)Math.Pow(2, 10);    // 1024, Pow도 double을 반환
int s = (int)Math.Sqrt(15);      // 3, 정수 제곱근(버림)
```

## 6. 오버플로: int 범위를 넘을 때

`int`는 약 ±21억(`2,147,483,647`)까지입니다. 넘으면 **오류 없이 값이 뒤집힙니다.**

| 코드 | 결과 | 설명 |
| :--- | :--- | :--- |
| `int.MaxValue + 1` (변수로 계산) | `-2147483648` | 오류 없이 음수로 |
| `a * 2` (`a = 2_000_000_000`) | `-294967296` | 곱셈도 마찬가지 |
| `(long)a + 1` | `2147483648` | 계산 **전에** `long`으로 바꾼다 |
| `2_000_000_000L * 2` | `4000000000` | 상수는 `L`을 붙여 `long`으로 |

- 곱셈, 누적 합, 경우의 수 계산은 처음부터 `long`으로 선언합니다.
- `(long)(a * b)`는 이미 넘친 뒤에 바꾸므로 소용없습니다. `(long)a * b`로 씁니다.
- 문제에서 "1,000,000,007로 나눈 나머지"를 요구하면 곱할 때마다 `% 1_000_000_007`을 합니다.

## 7. 문자열 ↔ 숫자

| 코드 | 결과 | 설명 |
| :--- | :--- | :--- |
| `double.Parse("1.5")` | `1.5` | 문자열을 실수로 |
| `(int)double.Parse("1.9")` | `1` | 실수 문자열의 정수 부분 |
| `3.14159.ToString("F2")` | `"3.14"` | 소수 둘째 자리까지 문자열로 (반올림) |
| `3.0.ToString()` | `"3"` | 소수점 아래가 0이면 생략된다 |

정수 문자열 변환(`int.Parse`, `TryParse`, 2진수 변환)은 [문자열 다루기](./string.md)의 6번에 있습니다.

## 고르는 기준

| 하고 싶은 것 | 쓸 코드 |
| :--- | :--- |
| 정수 부분 (양수) | `(int)x` |
| 내림 (음수 포함) | `(int)Math.Floor(x)` |
| 올림 | `(int)Math.Ceiling(x)` |
| 반올림 (사사오입) | `(int)Math.Round(x, MidpointRounding.AwayFromZero)` |
| 양수 올림 나눗셈 | `(a + b - 1) / b` |
| 큰 수 계산 | `long`으로 선언, 상수는 `L` |
